# 0019 官方一手优先的数据源分层与例外判据

date:          2026-10-16
supersedes:    -
superseded-by: -

## 背景

[0001](./0001-single-primary-source-tushare.md) 把采集收敛为「单一主源 TuShare Pro」（理由：口径一致、维护面不随源数增长）。
2026-10-16 逐条实测官方出口后（[data-source 附.11](../design/data-source.md)，证据脚本 `backend/scripts/spike_official_sources.py`）两个方向都出现偏差：

- 官网**可得且一手**的数据被无谓绕开（沪深交易所增减持/ETF 份额/两融、巨潮公告、中债 10Y）——它们可按**时间窗**增量取数，部分带**披露日**，可复算性优于转售；
- 官网**结构性不可得**的数据若强求官网会丢历史（官方 iVIX 2018 停发；港交所北向个股持股只留最近几季；月度开户数官方序列已断）。

## 决策

**默认不变**：TuShare Pro 仍是默认主源（行情/财务/分类/复权的历史深度与一致性由它保证），0001 的工程纪律（按 `trade_date` 批量、统一 client/限流/重试封装）原样保留。

**例外门**：某数据集**当且仅当**下列 5 条**全满足**时改以官方一手为主源，TuShare 退为回补与对拍：
① 官方是权威一手产地；② 出口可按**时间窗增量**取数（不得要求全量翻页——实测 AKShare 沪深增减持封装是全历史翻页且被限流断连）；
③ 带**披露时点**或明确可得时点（无披露日的源不得进回测/信号链路）；④ TuShare 没有、已受限，或口径需一手复算；⑤ 该指标要进信号链路。

分层与 `source_tier`：**L1 官方一手** → `official`；**L2 主源转售** → 按上游实际（上游是交易所则 `official`）；**L3 第三方编制**（东财/乐咕/optbbs）→ `highfreq`/`calc`，**禁入信号链路**。
**硬纪律**：增量键取披露日；类目/过滤参数必须**断言生效**（实测巨潮传无效 `category` 静默退化为全量）；单位与频率在 registry 固定；同一指标的 L1/L2 双源须对拍、**不得混算**，断点写 `caliber_version`。

## 影响

- 得到：Wave 1 遗留三条腿被解锁（产业资本增减持的两条官方路径、ETF 份额官方化、陆股通季度快照）；进信号链路的指标拿到一手口径 + 披露日，回测可复算。
- 代价：新增维护面——交易所接口无 SLA、沪深两所单位与 PIT 字段不对称、页面多为 JS 渲染（只能走接口）、需限速与断点续采。
- 遗留坑：港交所季度持股**错过当期即永久缺**（须落季度快照）；深市增减持**无披露日**；中证指数官方估值只有近 20 行。

## 备选方案与否决原因

- **一律改走官网（自建爬虫为主）** —— 丢掉主源唯一的长历史优势（官网历史不可回补，港交所仅留几季）。
- **维持现状（不改 0001）** —— 对官网可得的一手数据让出可复算性，并让 S1.7 的产业资本腿无谓阻塞到 Wave 2。
- **多源降级链** —— 0001 已否决：字段口径不可对齐时，「降级」本身就是数据事故。
