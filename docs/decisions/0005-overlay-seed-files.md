# 0005 人工策展数据用 overlay 种子文件，不改自动生成的种子

## 背景

部分数据需要人工策展（行业与标的的归属修正、特殊分类补充），它们必须进仓库以获得版本化与可复现性。但仓库里已有一批**自动导出的种子文件**（`sw_seed_raw.sql` 等），一旦被重新导出就会覆盖任何手工改动。

## 决策

- 人工数据放**独立 overlay 种子文件**，通过**加性 `ON CONFLICT`** 合并进主数据，不修改自动生成的种子
- 加载器显式支持 overlay 层，加载顺序在主种子之后
- 同步补两处豁免：`.gitignore` 的 `data/*` 与 `backend/.dockerignore` 的 `data/*`（否则镜像内文件缺失，加载器静默返回 0）

## 影响

- 得到：自动种子可随时重新生成而不丢人工成果；人工改动有独立 diff 与可追溯来源
- 代价：数据来源变成两层，排查"这条数据哪来的"需要同时看主种子与 overlay
- 坑：**漏 `backend/.dockerignore` 豁免 → 容器内加载器静默返回 0**（本地有数据、生产没有），这是最容易复发的一处

## 备选方案与否决原因

- **直接改自动生成的种子** —— 下次导出即被抹掉，且改动会被误认为机器产物
- **放数据库手工维护** —— 不可版本化、不可复现、无法 code review，与"数据即代码"的取舍相反
- **把人工数据混进生成器的输入配置** —— 会让生成器同时承担"采集"与"策展"两种职责，职责混淆
