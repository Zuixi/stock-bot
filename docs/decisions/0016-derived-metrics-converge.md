# 0016 派生指标由「对账后置收敛」日更，薄日不发布值

```
status:        accepted
date:          2026-10-16
supersedes:    -
superseded-by: -
```

## 背景

scope=`market` 的派生指标（spec §S1.7–§S1.13）**只有手工回补脚本**写它们，没有任何定时任务
调用过。于是 2026-10-12 那次人工回补之后，页面上的"数据截至 10月12日"三天不动，而
`daily_quotes` 天天在更新 —— 不是数据源问题，是一族 B 类可回算指标没接进日更链。

同日暴露第二个问题：合成指数的日历是"各成分可得日的并集"。回补那刻各腿锚点不齐（期货腿到
10-12、行情锚定的腿只到 10-09），于是长出一行 **3/11 条腿、权重 0.23** 的值并被当作"当天的
综合指数"发布 —— 它与前一日 10 条腿的值不可比。

## 决策

1. **不新开 cron**：收敛挂在对账之后（`reconcile_market_data_job` 尾步），复用三个触发点
   （启动 +2min / 交易日 17:45 / 每日 10:00）。底座先收敛，派生指标再按**同一个**
   `expected_latest` 推到 T-1 —— 顺序由代码保证，不靠时间差。
2. **电平触发 + 幂等自愈**：每轮重算最近 10 个**交易日**窗口；PG advisory lock 互斥；落后超
   60 个交易日不自动回补（只告警 + 手工入口），日更任务不该深夜要五年历史。
3. **发布闸门 0.80**（`COMPOSITE_PUBLISH_MIN_WEIGHT`）：权重和低于它 ⇒ 行仍在、参与集/权重/
   分位仍落 `extra`，但 `value=NULL` + `below_publish_weight`（值存 `extra.withheld_value`）。
   常态（只有 QVIX 缺值）为 0.88，仍在闸门之上 ⇒ 只挡结构性缺腿。
4. **读面只展示"各腿齐备到 T-1"的值**：hero 取最新一个过闸门的行，新增 `expected_as_of` /
   `lag_trading_days` / `stale`（三态，`null` = 判不出，**不得**读成"新鲜"）。
5. **手动轨道同源**：任务类型 `market_metrics` 调同一个 `converge()`。

## 影响

页面从"停三天"变成每轮对账后自动追到 T-1，薄行被重算覆盖成齐备值。代价：方法下限 0.20
不变，但 0.20–0.80 之间的日子不再产生值 —— 与 spec Ruling 66 的"薄值必须可见"字面冲突，
改由 `N/11 条腿`披露 + `stale`/`lag` 承担可见性。

## 备选方案与否决原因

- **独立盘后 cron（如 17:50）** —— 复现"任务准点跑才正确"的老坑：宿主睡眠、容器挂起、上游
  晚到都会算在半截底座上（10/12 正是这么来的），且 16:30/16:45 的分域对账之后 T-1 的限价
  与温度计还没齐。
- **只加一个复合指数 job** —— 复合指数是成分的派生（日历取并集），成分没推上去照样长薄行。
- **读时现算** —— 把写库、外呼与写锁放进读路径，违反 ADR 0014 的持久化边界。
- **把方法下限直接抬到 0.80** —— 那是改口径，需 bump `s1.13-v1` 并重写字典手算样例。
