# 0023 A股全景日级快照：广度/行业可回算，资金流只认完整日

```
status:        accepted
date:          2026-10-19
supersedes:    -
superseded-by: -
```

## 背景

`/market` 的「A股全景」五张卡此前全是**当日快照**：涨跌分布从 `daily_quotes` 现算
最近完整日、热力图现算、行业网格只读分类树、资金流读最新快照。用户无法回答
"今天比昨天变了什么"，而且三块卡的 `as_of` 实测不同（10-16 / 10-16 / 10-15），
资金流最新行还只是盘中 `poll` 子集（`eod_full` 只有 10-13 一天）。

要把这块升级为"持续跟踪"，必须先决定：**哪些历史值得落表、哪些允许现算、缺失怎么
表达**。如果只是给五张卡各加一条折线，会得到五个互不相干的时间轴，且历史口径随
代码版本漂移。

## 决策

### 1. 三张日表，按可回算性分类（沿用 ADR 0014）

| 表 | 一行 | 产地 | 回补 |
|---|---|---|---|
| `market_breadth_daily` | 一天 | B 类：`daily_quotes` + `stock_price_limits` | 允许（`source='backfill'`） |
| `market_breadth_bucket_daily` | 一天 × 11 桶 | B 类，与 `/market/distribution` **逐字同口径** | 允许 |
| `market_industry_daily` | 一天 × 31 个申万一级 | B 类聚合 + **C 类归属** | 允许，但归属是**当前**申万快照 |

- 行业归属写 `attribution='current_sw_snapshot'`；UI 固定文案「行业归属：按当前申万
  快照回溯」。不承诺"当时成分"。
- 资金流**不新建表**：继续用 `sector_moneyflow_snapshots`，A 类不可回补；只把
  `/market/sector-moneyflow` 的读日闸门改成 **`capture_kind='eod_full'`**。此前取
  `max(trade_date)`（任意产地）会把 10-15 的盘中 Top-100 子集当"末完整日"，与卡片
  自己的维度说明不符，也和全景脉搏出现两个 `as_of`。
- 缺完整日 → 资金流 `flows=null` / 卡片空态，**不拿 poll 子集冒充**、不补 0。

### 2. 广度口径与涨跌分布卡一致

"上涨" = `pct_chg >= 1%`，"平/微涨" = `0 <= pct_chg < 1%`，"下跌" = `pct_chg < 0`。
这不是自然语言里的"上涨/平盘"，而是既有 `/market/distribution` 11 桶的聚合语义
（`1~3% + 3~5% + >5% + 涨停` / `0~1%` / 负桶）。新表必须与卡片逐字对齐，否则同屏
会出现"上涨 2,105"与"上涨 3,300"两个都自称正确的数。

### 3. 市场结构状态是启发式描述，不是交易信号

用**广度（上涨占比）+ 集中度（Top3 行业成交额占比）+ 中位涨跌幅**判四态：

| 条件 | 状态 |
|---|---|
| 上涨占比 ≥ 60% 且 Top3 < 35% 且 中位 > 0 | 普涨 |
| 上涨占比 ≤ 40% 且 Top3 < 35% 且 中位 < 0 | 普跌 |
| Top3 ≥ 45% | 抱团 |
| 其余 | 结构 |

加中位数的原因（2026-10-16 真库）：上涨占比 37.8%，但中位 +0.47%、上涨 2,105 /
下跌 2,125 —— 只看广度会判成"普跌"，实际是"指数涨、个股分化"。中位数是"典型个股"
的方向，必须同看。阈值写死、可复核；UI 固定"启发式，不是交易信号"。

### 4. 读面一次请求、不 N+1、<100ms

`GET /market/panorama?days=60` 只读日表：

- 60 天广度 1 条；60 天结构在 SQL 内聚合（Top3/HHI/离散度，**不是**把 7,750 行行业
  明细读进 Python）；最新行业 31 行 + 昨日排名 31 行；11 桶 1 条；资金流 2 条；
- Redis 120s；响应自带 `as_of/expected_as_of/stale/lag_days` 与
  `freshness.flow_as_of/flow_available_from`；
- 实测（本地真库，ASGI 冷请求）：20D 19ms / 60D 21ms / 120D 24ms / 250D 31ms；
  250D 响应 99KB；Redis 命中 4–6ms。

### 5. 回补是显式脚本，不在请求里现算历史

`backend/scripts/backfill_market_panorama.py`：默认从 `2025-10-15`（限价安全窗口）起，
一条 SQL 算一天广度/11 桶、一条 SQL 算行业；`ON CONFLICT` 幂等，可 `--dry-run`。
本地回补 244 天 / 2,684 桶 / 7,564 行业行。历史只补一次；之后由日终 job
`market_panorama_daily`（17:25，晚于 16:30 行情 / 16:50 限价）幂等续写。

## 被否决的方案

- **给五张卡各加折线**：五个独立时间轴、没有共享 `as_of`，回答不了"结构"。
- **全景接口现算 60 天行业**：5,500×60 行扫描，冷请求 >1s，违背 <100ms。
- **资金流回补**：东财只给当日/最近，历史不可得；假装有历史是造假。
- **把 poll 行当完整日**：Top-100 子集不是全量榜，连续性/排名都会错。
- **用 ML/聚类判状态**：样本短、不可复核、无法解释"为什么今天是结构"。

## 后果

- 新增迁移 `e3f1a7c9d2b4`；三张表 + 回补脚本 + 一个**纯本地**日终 job（17:25）；无新外部依赖。
- `/market` 第一屏多一条「市场结构脉搏」；涨跌分布加"较昨日/5 日上涨占比"；行业
  网格加今日涨跌角标；热力图可切"今日/昨日"（`GET /market/sectors?date=`）。
- 资金流卡会更旧（10-13 而不是 10-15）——这是**正确**的：旧的是完整日，新的是
  盘中子集。UI 必须继续显示 `stale_days`，不得隐藏。
- 未做（明确边界）：跨卡行业筛选、热门板块"新进/掉出"、热力图 5D/20D 区间。
