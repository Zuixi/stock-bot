# 0020 当日盘后（T+0）纳入数据面期望集：期望日看日历时钟，齐备性另设门禁

```
status:        accepted
date:          2026-10-17
supersedes:    -
superseded-by: -
```

## 背景

2026-10-16（周五）22:30 用户报："已经 16 号了，`/sentiment` 的 hero 还显示 15 号，为什么不会
自动刷新"。实测（真库 + API + scheduler 日志）：

| 事实 | 证据 |
|---|---|
| 库里**根本没有**当日行情 | `daily_quotes` `max(trade_date)=2026-10-15`，无 10-16 任何一行 |
| 综合指数最新行 = 10-15 | `industry_metrics` 最大 `period=2026-10-15`（9/11 条腿、`effective_weight=0.84`） |
| 后端自称"不滞后" | `GET /market/sentiment/composite` → `as_of=expected_as_of=2026-10-15`、`lag_trading_days=0`、`stale=false` |

两条独立缺陷叠加：

1. **期望集硬编码"截止昨日"**：`reconciliation_service.expected_trade_dates` 里
   `end = today - 1`。于是当日行情**永远**不进 `daily_quotes`（对账的期望集里从来没有今天），
   下游派生指标的收敛目标 `expected_latest` 也就永远是 T-1 —— 页面"数据截至"天天不动，
   而底层数据源其实一切正常。这不是数据源问题，是**口径问题**。
2. **新鲜度判据自指**：hero 的 `expected_as_of` 取自 `resolve_latest_complete_day`，而那个
   候选日就是 `max(daily_quotes.trade_date)` —— 与被判据的对象**同源**。于是"今天整天没采"
   时期望日跟着退回昨天、`stale` 恒为 `false`：判据永远自洽、永远不报警，比不显示更糟
   （它让读者确信数据是新鲜的）。

同日实测的可行性证据（只读探测上游，2026-10-17 00:2x，距周五收盘 9.4 小时）：

| 来源 | 目标日 2026-10-16 |
|---|---|
| TuShare `daily` / `daily_basic` / `stk_limit` | 5567 / 5567 / 5655 行，**含当日** |
| TuShare `fut_daily` / `index_daily` | 含当日（基差腿、换手率腿） |
| TuShare `margin` | **0 行**（交易所 T+1 披露；10-13/14/15 均已有） |
| akshare QVIX CSV | `max_date=20261016`；`Last-Modified` = 10-16 **16:53 CST** |

⇒ 当日盘后可得 9/11 条腿、生效权重 0.84，仍在发布闸门 0.80 之上。

## 决策

### 1. 「该到哪天」与「真到没到」拆成两个判据

- **期望日**（`market_day_service.calendar_expected_latest_day`）：纯函数，**只**由交易日历
  与时钟决定 —— 交易日且已过 `T0_CUTOFF`（17:30 CST）⇒ 当日；否则上一交易日。
  **不探库、不看行数、不看齐备性。**
- **齐备守门**（`reconciliation_service._gated_expected_latest`）：对账把底座补齐**之后**，
  从期望上界往前找"最新一个过 `market_day_service.day_is_complete` 三元组门禁的日子"，
  不达标逐日回退；一个都不过 ⇒ `None`（宁可这一轮不收敛，也不在半截底座上算指标）。

**为什么必须拆开**（合一即出两种死锁）：

1. 对账拉取**之前**，当日必然没有数据；若期望日要看齐备性，当日永远进不了期望集
   ⇒ 当日行情永远拉不到（鸡生蛋）。
2. 读面新鲜度若也看齐备性，"今天整天没采"时期望日退回昨天 ⇒ `stale=false`
   —— 背景里的缺陷 2 原地复活。

### 2. cutoff = 17:30（Asia/Shanghai），不新开 cron

取值同时满足三件事：晚于 16:50 的限价入库（`is_day_complete` 的第三项就是"该日有限价"）、
早于 17:45 的既有全量对账 —— 于是 **17:45 那一轮自动成为 T+0 收敛点**。

当日数据未出全时拉了会写 partial（2026-09-16 事故）—— 这是"当日进期望集"必须晚到收盘后
的**唯一**理由，故 cutoff 不得前移。

### 3. 齐备判据统一到 `is_day_complete`（修掉阈值分叉）

对账原先用 `COMPLETENESS_RATIO = 0.8` 的行数门槛决定"要不要重拉"，而读面用
0.9 + 列级 + 限价。行数落在两者之间的日子会被判"已 OK、无需重拉"却又永远过不了读面门禁
⇒ **当天卡在 T-1 且永不自愈**。统一到更严的那个，并让"过不了门禁"的日子重新进重拉队列。

### 4. 落后天数用**日历计数**，不用"行情表实际持有"

`lag_trading_days` 原本数 `daily_quotes` 里 `(as_of, upto]` 的 DISTINCT 日期。在"今天整天
没采"这个正要修的场景里，行情表里没有今天 ⇒ 数出 0 ⇒ `stale=false` —— 自指以另一种形式
复活。改由缓存日历计数：日历是**外部事实**，不随"我们采到了什么"变化。

### 5. 交易日历进 Redis，读面不外呼

key `market:day:trade_calendar`，载荷 `{days, covered_through}`，TTL 7 天，由对账在
`degraded=False` 时写（工作日启发式**不入缓存**，否则把节假日误判固化 7 天）。

**`covered_through` 是必需字段**：只存日期列表分不清"今天休市"与"缓存停在昨天"，后者被当成
"今天不是交易日"会让期望日静默退回昨天。覆盖不到今天一律返回 `None`（判不出，不许猜）。

`date` 两侧都显式 ISO：`CacheClient` 走 orjson，`date` 不是原生类型；"写进去是 date、读回来
是 str"会让 `day <= today` 抛 `TypeError`。

### 6. T+0 值是**临时值**，读面照实说（三态）

交易所融资融券是 T+1 披露 ⇒ 当日盘后读到的合成值**必然**缺这两条腿（合计权重 0.16），而它们
会在上游披露后被收敛器重算改写。故 hero 新增 `provisional` 三态：

- `True` = 缺**已声明的** T+1 成分（`industry_registry.COMPOSITE_LATE_ARRIVAL_KEYS`）且仍在
  收敛改写窗口（与 `CONVERGE_WINDOW_TRADING_DAYS` 同值）内 ⇒ 这个数字以后会变；
- `False` = 终值（腿齐，或已落到改写窗口之外、收敛器再也不会碰它）；
- `None` = 判不出（缺参与集登记 / 缺交易日历）—— **不得**归并成 `False`（那会把"不知道"
  说成"是终值"）。

**披露口径**：文案写"待上游披露后重算"，**不写"次日"** —— 实测 10-15 的融资融券到 10-16
21:32 仍未披露，承诺具体时点会直接失实。

### 7. 重试 tick 与"顺序由代码保证"

- 17:45 是当天唯一一次机会，上游晚到半小时就要等到**次日 10:00** 兜底对账。故加
  `reconcile_retry_1830` / `reconcile_retry_2000`，但它们**先做零外呼判定**（期望日是不是
  今天、今天是否已过门禁），只在真的还没齐备时才跑整条链 —— 因为收敛器的波动率腿声明了
  `always_rescan=True`（QVIX 迟到补数），**每轮都会真外呼**。
- 个股级涨停事实（`limit_up_stock_daily`）在 `INSPECT_DOMAINS` 里，对账**永不自愈**它，而它的
  `as_of` 取自"最新完整交易日"。故把它串成对账尾步（`_refresh_limit_up_facts`），而不是把
  cron 挪到 17:55 靠时间差避让 —— 当日全量拉取在 TuShare 节流下可能好几分钟，时间差排序必然
  偶发踩空（[ADR 0016](./0016-derived-metrics-converge.md) 同款纪律：顺序由代码保证）。

### 8. 不做的事

- **不新增表、不加迁移**：复用 `industry_metrics` / `daily_quotes` / Redis 日历键。
- **不改任何计算口径**：发布闸门 0.80、分位窗口 1260、`caliber_version`、权重与归一化规则
  一律不动；`provisional` 是**同口径的时序事实**，故不升版、不新增 `metric_key`。
- **不做盘中**：只做盘后。盘中实时读面已有独立轨道（东财涨停池 / `market_sentiment_intraday`）。
- **读面不轮询上游**：不在 GET 里外呼 TuShare；前端只在 `stale=true` 时低频探测。

## 影响

- 交易日收盘后（≥17:30 + 对账跑完）页面显示**当日**数据；数据没到就如实报"落后 N 个交易日"。
- `provisional=true` 的当期值会在上游披露后被改写 —— 这是本决策**唯一**的产品级代价，已用
  三态披露显式化（读者若引用需自行判断）。
- 对账多了一次 `trade_cal` 外呼与每日两次条件 tick（无缺口时零外呼）。
- `env` 开关 `T0_AFTER_CLOSE_ENABLED` 可一键退回 T-1 语义。**注意**：关掉它会让新鲜度报
  "无法判定"，而**不是**恢复自指锚 —— 自指锚是本次明确要拆掉的东西。

## 备选方案与否决原因

- **只把读面锚改成日历、不动期望集**：能立刻消除"假新鲜"（这是好事，已包含在本决策里），
  但页面仍然只到 T-1 —— 用户诉求（收盘后看到当天）没解决。
- **把期望集上界放宽到"今天任意时刻"**：会在盘中/收盘前拉到半截数据并写 partial
  （2026-09-16 事故的成因），且读者的完整性门禁只能挡住一部分下游。故必须设 cutoff。
- **给当日值单独一套闸门/口径**（把 T+1 腿排除出分母）：属口径变更，且会让"当日值"与
  "历史值"不可比。实测当日 0.84 > 0.80 本就发得出来，不需要例外。
- **`provisional` 写库成 `extra` 键**：历史行缺该键会被 `default False` 读成"是终值"
  —— 又一次"缺键 = 撒谎"。改为读时由 registry 推导，历史行自动正确。
- **把重试 tick 直接挂 `reconcile_market_data_job`**：波动率腿每轮真外呼，成本随 tick 数线性
  上涨。改为条件 tick。
