# 0009 原料/视图分离

```
status:        accepted
date:          2026-10-12
supersedes:    -
superseded-by: -
```

## 背景

10 张 owner 思维导图里，同一批原料被多个视图消费：政策文本 → 资讯 / 宏观产业政策 / 政策影响追踪；
公告 → 资讯 / 公司事件驱动 / 情绪产业资本增减持；研报 → 资讯 / 行业有效研报 / 宏观预期差基准 / 价值网产业链边；
行情、财务、两融同理。

## 决策

- **采一层**：原料由采集/抽取写入，一源一份。
- **存一层**：事实行只由采集/抽取写入，不携带任何用户维度状态。
- **多视图读**：视图是对事实行的投影（筛选 + 排序 + join），不各自持有副本。
- **用户状态（已读/已处理）必须落用户维度表**，以 `(user_id, 事实行主键)` 建键；
  **不得写在事实行上**——事实行是共享的，写上去等于把一个人的状态广播给所有人。

## 影响

- 得到：一次采集多处复用；用户状态不串；新增视图不触发重复采集。
- 代价：视图层需 join，读路径变复杂，必要处要缓存/物化。

## 备选方案与否决原因

- **每模块各自采集** —— 重复抓取、去重口径不一致，同一公告在三处显示不同"已读"状态
- **先建宽表后按需拆** —— 宽表被多视图需求拉扯成孤儿列
