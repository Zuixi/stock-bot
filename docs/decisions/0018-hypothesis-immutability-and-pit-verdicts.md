# 0018 研究假设写下即冻结，判定是三态且受 PIT 约束


## 背景

主线计划 §4 把「研究 → 决策」「执行 → 研究」两条回路定为**产品成败所在**，但它们在路线图里排在 Wave 5/6。
而 2026-10-16 的代码实测显示：读面（行情 / 看板 / 情绪）已建成约 21 个实页面，
研究工作流侧**只有**「自选 + 标签」两件资产 —— 全库唯一的用户自由文本是
`user_watchlist_items.notes`，**假设、结论、证据链、导出、复盘全部零代码**。
即：看完之后无处可写，产品停在"看板"。

同时，承接它的地基都已就绪：`industry_metrics` 统一读面（[S1.2](../specs/S1-market-sentiment.md)）、
纯函数规则 + registry 阈值（`cycle_engine.py` 形态）、对账尾步挂载点（[ADR 0016](./0016-derived-metrics-converge.md)）、
PIT 契约（[ADR 0011](./0011-point-in-time-data-contract.md)）。

## 决策

**① 假设是用户资产，独立成表，不塞进 `industry_signals`。**
后者是**系统信号流**（无作者、无到期日、无状态机），与"谁在什么时候提出了什么可验证判断"是两种语义；
混装会让"这条信号是系统算的还是人写的"成为永久二义，且与 S2.2 已定的 4 列扩展冲突。

**② 写下即冻结。** `claim` / `conditions` / `deadline` 创建后**不可 UPDATE**，接口层**不提供**
PATCH / PUT / DELETE；要改就作废 + 新建。撤回是**新增一条事件**（`withdrawn`），且**计入准确率分母**。
理由：允许事后修改判定条件，"准确率回看"就是自欺 —— 而准确率是本功能唯一的产出物。

**③ 判定结论是三态，且受 PIT 约束。**
`passed` / `failed` / **`insufficient_data`**；**缺数据绝不等同于不满足**（否则一次上游故障会把假设判成证伪，
准确率当场被污染）。判定取数只用 `period >= hypothesis.created_at::date`，**绝不用假设写下之前的行情**。

**④ 期间只可能判"成立"，不存在"提前证伪"。**
只要未到期，就无法断言"它再也不会满足"；硬要提前判证伪必然引入拍脑袋规则。
故 `falsified` **只来自到期未达**，期间的信息由**读时计算的进展**表达（"3 条已满足 2 条"），不冒充终局。

## 影响

- 判定挂 `reconcile_market_data_job` 尾步、**必须排在 `derived_metrics_converge` 之后**（否则会拿薄行当结论），
  **不新开 cron**；PG advisory lock + `unique(hypothesis_id, kind, as_of)` 保证重跑幂等。
- 新增 **3 张表**（假设 / 事件 / 铃铛游标），故 S2 的「新增表仅 3 张」判据随之改为 **6 张**，
  每张的存在理由记在 [S2.5](../specs/S2-signal-engine.md)。
- 三态必须在 UI 上**视觉可分**（`数据不足` 不得渲染成"未满足"）并有前端 Playwright e2e 锁定 ——
  判定引擎再严谨，UI 画错则全部作废。
- 证伪线（"若 X 则本轮判断失效"）是真实研报最常写的一句，本批**不做**，列为 v2 第一优先项。

## 备选方案与否决原因

- **复用 `industry_signals` 当假设表** —— 需加 6+ 列并接受语义二义；"按作者回看准确率"无法机械表达。
- **条件与判定全塞 JSONB 单表** —— 条件无法被唯一键、索引与门禁脚本断言，证据链只能应用层扫；
  本仓的取向是"能机械化的必须机械化"。
- **允许编辑假设（对用户更友好）** —— 直接摧毁准确率回看，即本功能存在的理由。
