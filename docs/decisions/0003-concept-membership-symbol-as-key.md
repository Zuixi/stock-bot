# 0003 概念成分以 symbol 为业务键，stock_id 降级为可空解析列

```
status:        accepted
date:          2026-09-18
supersedes:    -
superseded-by: -
```

> 追认补录（2026-09-23）。来源：`plans/2026-09-18-concept-boards-and-new-stocks.md`、`docs/references/best-practices.md`「概念板块」相关条目。

## 背景

概念板块成分数据来自东财/同花顺等当前快照型接口，其中包含**名录里还没有的标的**（次新股、改名股）。原设计以 `stock_id` 作外键并强制解析，映射不到的行只能 `skipped += 1; continue` —— 数据静默丢失，且日志无法回答"丢了多少、丢了谁"。

## 决策

- 成分表以 **`symbol` 为业务键**（上游给什么就存什么），`stock_id` 降为**可空解析列**
- 未解析数量以 `unresolved_count` 显式回传，而不是在采集期吞掉
- 读路径以 `symbol` 匹配行情，不依赖 `stock_id` 非空

## 影响

- 得到：名录滞后不再等于数据丢失，缺口变成可观测指标；次新股行情能在名录刷新前先落成分
- 代价：JOIN 需处理 `stock_id IS NULL`；下游需要接受"有成分但无名录信息"的中间态
- 同源教训（同批修复）：**翻页护栏的页数上限必须由真实最大分页数推导**（原 `_MAX_PAGES=20` < 某板块 3870 成分，导致该板块因内连接而在所有视图中完全不可见）；**完整性闸门必须先清洗再比总数**（否则脏行抬高计数掩盖少抓）

## 备选方案与否决原因

- **保持 `stock_id` 必填** —— 静默丢数，且丢的是最新标的（新股/次新），恰好是最有分析价值的一类
- **先补名录再入成分** —— 名录刷新与成分采集是两条独立管道，强制时序会把一次上游延迟放大成长期缺口
