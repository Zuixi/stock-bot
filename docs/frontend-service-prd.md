# Stock Bot 前端服务 PRD（Web）

## 1. 文档信息

- 文档版本：v1.0
- 创建日期：2026-04-07
- 适用范围：`stock_bot` 前端 Web 服务（React 18 + Vite + ECharts + Tailwind + shadcn/ui）
- 关联文档：`docs/web-prd.md`、`docs/ARCHITECTURE.md`、`product.md`
- 参考视觉：FinScope 风格市场总览页（用户提供截图）

## 2. 背景与目标

### 2.1 背景

当前项目已经明确后端数据服务方向（FastAPI + PostgreSQL + Redis + RabbitMQ），并逐步覆盖三大交易所股票池与行情数据。前端需要承接这些数据，提供统一、清晰、可筛选、可追踪的可视化入口，帮助用户从“市场全貌”快速下钻到“个股细节与基本面”。

### 2.2 产品目标（本阶段）

本阶段前端目标是“先把数据完整展示出来，并可高效检索与分类查看”：

1. 展示全市场与分类维度的数据总览（交易所、行业、板块、榜单）。
2. 提供个股详情页，展示行情、关键指标与基础面信息。
3. 支持分类查看、筛选、排序、搜索、自选与多维切换。
4. 为后续 UX 深化与架构扩展提供稳定信息架构与接口约束。

### 2.3 非目标（本阶段不做）

- 不提供自动交易、下单能力。
- 不输出“买卖建议”类结论（仅做数据展示与分析辅助）。
- 不做高复杂社交功能（如赏金众包、评论社区）上线，仅预留导航占位。
- 不实现重度可视化编辑器（保持可维护的标准 dashboard 交互）。

## 3. 目标用户与核心场景

### 3.1 用户画像

1. **个人投资者（主要）**
   - 关注市场强弱、行业轮动、个股相对位置
   - 需要快速浏览 + 快速下钻
2. **研究/量化分析用户（次要）**
   - 关注分类统计、历史变化、可比性
   - 需要稳定字段、统一口径和可追溯数据时间戳

### 3.2 核心使用场景

1. 打开“市场”页，先看全球/全市场状态，再查看 A 股细分结构。
2. 在分类列表中按交易所/行业/板块筛选，按市值/涨跌幅/成交额排序。
3. 搜索或点击个股，进入详情页查看行情与基本面摘要。
4. 添加到自选后在“自选”页持续追踪变化。
5. 对比行业内个股与大盘表现，辅助形成后续研究判断。

## 4. 信息架构（IA）

### 4.1 一级导航（本阶段）

1. 市场（核心，优先级 P0）
2. 资讯（P1：先做结构和列表）
3. 自选（P0）
4. 工具（P1：以数据资料入口为主）
5. 价值网（P2：先占位，不上线复杂图谱）
6. 赏金榜（P3：仅导航占位）

### 4.2 页面结构

1. 市场首页（Dashboard）
   - 全球市场条（指数卡片）
   - 自选速览区
   - 行情中心（分布图、热力图、资金流、行业强弱）
   - A 股热门板块/主题列表
2. 分类市场页
   - 按交易所 / 一级行业 / 二级行业 / 板块分类查看
   - 支持排序、筛选、分页与指标切换
3. 个股详情页
   - 头部摘要（代码、名称、交易所、所属分类、最新价、涨跌）
   - 行情图表（K 线 + 成交量 + 区间切换）
   - 基本面卡片（市值、PE、PB、ROE、营收/利润增速等）
   - 关联信息（公告、财报、新闻，P1）
4. 自选页
   - 自选分组、排序、涨跌提醒（P1）
5. 搜索结果页/全局搜索下拉
   - 支持股票代码、名称、拼音简码（P1）

## 5. 功能需求（按优先级）

### 5.1 P0（必须上线）

#### FR-001 市场总览

- 展示三大交易所及核心指数卡片：最新点位、涨跌额、涨跌幅、更新时间。
- 支持市场维度切换（亚洲/美洲/欧非占位，A 股优先完整）。
- 卡片点击可进入对应分类页。

**验收标准**
- 首屏在 3 秒内渲染核心卡片（有缓存条件下）。
- 指标单位与颜色语义统一（涨红跌绿或反之需全站一致）。

#### FR-002 分类查看与筛选

- 提供交易所、一级行业、二级行业、板块等分类维度。
- 支持按总市值、涨跌幅、成交额、换手率排序。
- 支持筛选条件组合（交易所 + 行业 + 区间涨跌）。

**验收标准**
- 切换分类后列表和图表同时更新。
- 排序规则稳定且支持升/降序切换。

#### FR-003 行情中心可视化

- 支持至少以下图表模块：
  - A 股涨跌分布（柱状/分段）
  - 行业热力图（Treemap）
  - 主力净流入排行（柱状）
  - 热门板块列表（含迷你趋势线）
- 图表支持 tooltip、图例、空态、加载态。

**验收标准**
- 图表与列表指标口径一致（同一时间点）。
- 图表在无数据时显示可理解空态，不报错。

#### FR-004 个股详情页（行情 + 基本面）

- 展示个股基本信息：名称、代码、交易所、行业分类、上市状态。
- 展示行情信息：最新价、涨跌、振幅、成交量、成交额。
- 展示基础面信息：总市值、流通市值、PE(TTM)、PB、ROE、营收同比、净利润同比（按可得数据降级）。
- 展示历史行情图：1D/5D/1M/3M/6M/1Y（至少日频完整）。

**验收标准**
- 打开详情页后 2 秒内可见骨架与关键数值。
- 缺失字段需展示 “--” 并附字段说明，不可出现 NaN/undefined。

#### FR-005 自选管理（基础）

- 支持添加/移除自选股。
- 支持自选列表按涨跌幅/市值排序。
- 支持本地持久化（未登录）+ 账号持久化（登录后，P1 可增强）。

**验收标准**
- 添加/取消自选响应小于 300ms（前端交互反馈）。
- 页面刷新后自选状态保持一致。

### 5.2 P1（次阶段）

#### FR-006 全局搜索
- 支持按代码、名称检索。
- 支持模糊匹配与最近搜索历史。

#### FR-007 资讯与公告聚合
- 个股详情关联公告/财报/新闻摘要。
- 市场页展示重点公告时间线。

#### FR-008 分类变动追踪
- 行业/板块排名变化（如 `↑2`、`↓1`）。
- 提供日/周维度切换。

### 5.3 P2（预研/占位）

#### FR-009 价值网
- 公司-行业-主题关系图谱（先定义数据接口，不做复杂交互）。

#### FR-010 高级对比
- 多股票对比（收益、波动、估值分位）与导出。

## 6. 关键业务规则与口径

1. 交易所命名与后端保持一致：`Shanghai_Stocks`、`Shenzen_Stocks`、`Beijing_Stocks`。
2. 分类优先使用交易所官方分类，跨交易所统一分类作为后续增强能力。
3. 所有展示指标必须带“数据时间戳（asof）”。
4. 数值展示规则：
   - 百分比统一保留 2 位小数
   - 金额支持万/亿格式化
   - 大数值显示千分位
5. 风险提示文案固定出现在详情页与分析模块：仅供参考，不构成投资建议。

## 7. 数据需求与接口契约（前后端协同）

### 7.1 前端所需核心数据域

1. 市场指数数据（多市场）
2. 股票列表数据（分类、分页、排序）
3. 个股实时/准实时快照
4. 个股历史行情（OHLCV）
5. 基本面指标（估值、盈利、成长、财务摘要）
6. 行业/板块统计与资金流向

### 7.2 接口契约要求

1. 列表接口必须支持：`page`、`page_size`、`sort_by`、`sort_order`、`filters`
2. 图表接口必须支持时间区间参数：`range`、`start`、`end`
3. 响应结构必须包含：
   - `asof`（数据时间）
   - `source`（来源标识，可选）
   - `version`（口径/模型版本，可选）
4. 错误结构统一：`code`、`message`、`details`

### 7.3 缓存与刷新策略（建议）

1. 市场总览：30-60 秒缓存
2. 列表与分类统计：60-300 秒缓存
3. 个股详情快照：15-60 秒缓存
4. 历史行情：按日期维度长缓存 + 条件刷新

## 8. 交互与 UX 约束（供 UX 设计直接使用）

1. 首屏采用“总览 -> 下钻”结构，优先可读性和扫描效率。
2. 所有页面都应支持：
   - 加载态（Skeleton）
   - 空态（无数据引导）
   - 错误态（可重试）
3. 分类切换位置固定在内容上方，避免随页面滚动消失（桌面端）。
4. 图表与列表联动时，必须保留当前筛选上下文。
5. 个股详情信息分区清晰：行情、基本面、资讯分块可折叠。
6. 主题风格先使用浅色主题，暗色主题作为后续增强。
7. 响应式要求：
   - 桌面端优先（>=1280）
   - 平板可用（>=768）
   - 手机端保证核心浏览与搜索可用（图表可简化）

## 9. 非功能需求（NFR）

1. 性能
   - 首屏 FCP < 2.5s（网络良好场景）
   - 路由切换可交互时间 < 1.5s
2. 可用性
   - 核心页面可用性 99.5%（月）
3. 稳定性
   - 图表渲染错误不得导致页面崩溃
4. 安全与合规
   - 不在前端暴露敏感密钥
   - 全站展示风险提示，不输出投资建议措辞
5. 可观测性
   - 接入前端埋点：页面访问、筛选行为、详情访问、搜索行为、错误事件

## 10. 里程碑与交付范围

### M1（2-3 周）：数据展示 MVP

- 完成市场首页、分类列表、个股详情（行情+基本面）与基础自选
- 打通核心 API，完成状态管理与基础缓存

### M2（2 周）：体验增强

- 全局搜索、资讯聚合、行业/板块变动追踪
- 优化图表交互与错误恢复

### M3（2 周）：可运营化

- 完善埋点、告警、性能优化、灰度发布策略
- 输出 UX 设计规范补充与前端架构决策记录（ADR）

## 11. 验收标准（Release Gate）

上线前必须满足：

1. P0 功能全部通过验收用例。
2. 核心路径（市场首页 -> 分类 -> 个股详情 -> 加入自选）全链路可用。
3. 核心图表均有加载态、空态、错误态。
4. 关键指标显示口径与后端文档一致（抽样核对）。
5. 无阻断级前端错误（P0/P1 bug 为 0）。

## 12. 风险与应对

1. **数据字段不完整/变动**
   - 应对：前后端字段契约版本化，前端做降级兜底显示。
2. **分类口径跨交易所不一致**
   - 应对：先按交易所官方分类展示，统一口径放在 P1/P2。
3. **图表性能压力**
   - 应对：大数据量分页与采样、懒加载、虚拟列表。
4. **需求膨胀**
   - 应对：严格按 P0/P1/P2 分层交付，冻结当期范围。

## 13. 待确认事项（Open Questions）

1. 基本面字段的权威数据源与更新频率最终选型。
2. 未登录用户自选数据是否允许跨设备同步（需账号体系支持）。
3. 资讯模块数据来源与版权/合规边界。
4. 是否在 M2 引入“个股对比”功能，或延后到 M3。

## 14. 附录：建议的前端模块划分（供架构设计起点）

1. `apps/web`：前端主应用（路由、布局、主题）
2. `features/market`：市场总览与分类模块
3. `features/stock-detail`：个股详情模块
4. `features/watchlist`：自选模块
5. `features/search`：全局搜索模块
6. `entities/stock`：股票领域模型与字段映射
7. `shared/api`：API client、错误处理、缓存策略
8. `shared/ui`：图表组件、通用表格、状态组件（Skeleton/Empty/Error）
