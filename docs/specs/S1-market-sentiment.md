# S1 市场 + 情绪（Wave 1）

> 本文件是**契约**，不是排期。执行清单见主线计划 §7 Wave 1。
> **Wave 1 的核心判据**：这一波**完全不依赖资讯（S3）**——市场与情绪是全项目唯二"纯数值、零文本依赖"的模块，因此可以先行。

**为什么市场与情绪必须并行做**：两者共用大量数据（成交额 / 换手率 / 涨跌家数 / 两融 / 涨跌停），且情绪分析是 `S6.2 择时策略` 与 `S6.3 信号系统（四维评分中的情绪因子）` 的**唯一来源**。

## S1.2 `industry_metrics` 扩展与统一读面

**范围**：做完之后，任何新指标（情绪、宏观、行业、策略因子）都写入叫 `industry_metrics` 的那张既有表、走同一套读 API，不新增指标表。

**这是 Wave 1 的拱心石**：S1.3–S1.14 全部依赖它。

**为什么不建新表**：`backend/app/models/industry_research.py:30` 的 `industry_metrics` **已经**是统一指标表的形状——`(industry_key, stock_id, metric_key, source, source_tier, freq, period, value, unit, extra)` + 6 列唯一键 + 2 索引 + registry 配置。**新表只多两个字段，却要多一套模型 / 迁移 / 读写 API / 缓存 / 幂等校验。** 原方案（新建 `metric_series`）已撤销，见 [S0.1 ADR-E 附带裁定](./S0-platform-contracts.md#s01-平台决策-adr-批次5-篇)。

**交付物**
- Alembic 迁移：`industry_metrics` **加 2 列**
- `backend/app/services/industry_registry.py` 扩展：登记新指标的 `{名称, 单位, 频率, 数据源优先级, 参考区间, 展示分组, 口径版本}`
- `backend/app/api/v1/metrics.py`：统一读端点（**优先复用既有 metering 端点，缺口才补**）
- 前端 `<MetricBadge>`：`source / as_of / freq / 口径版本` 四徽章（**复用既有 `SourceBadge`**，不新起组件）

**契约**

```sql
alter table industry_metrics
  add column published_at    timestamptz,   -- ★ PIT：实际可得时点（ADR-C）
  add column caliber_version text;          -- 口径版本；上游口径修订时必须填

-- 索引：按 scope + metric 的时序查询已有
--   unique (industry_key, stock_id, metric_key, source, freq, period)
--   idx    (industry_key, metric_key, period)
-- 不新增索引，先量测；确慢再加
```

> `ponytail: industry_key 现被当作通用 scope 键（'pig' / 'market' / 'broiler'），语义已泛化——情绪与宏观指标用 industry_key='market' 落进来。第二次接入非行业 scope 时改名为 scope_key。`

**端点（复用优先，逐个确认既有覆盖度）**
- `GET /api/v1/metrics/latest?scope_keys=&metric_keys=` → 每指标最新值 + `source/as_of/freq/caliber_version`
- `GET /api/v1/metrics/series?scope_key=&metric_key=&range=` → 升序序列，Redis 缓存
- `POST /api/v1/metrics:batch` → 人工/CSV 导入，源白名单校验（沿用既有 `batch_import_whitelist` 模式）

> 既有 `/api/v1/industries/{key}/metrics/*` 已覆盖行业 scope 的大部分需求。**先看缺口，再决定新端点**——不要平行造一套。

**PIT 约束（硬性）**：`published_at` 允许为 NULL（行情等"发布即连续可得"的序列），但**任何被规则/回测引用的序列必须非空**——由 [S2.2](./S2-signal-engine.md) 在读取时护栏报错，**不得静默回退到 `period`**。

**依赖**：S0.1（ADR-C / ADR-E）、S0.4（`metric_key` 命名）
**验收判据**
- 数据契约：迁移**只加 2 列**；`grep -rn "create_table" backend/app/migrations/versions/*.py | grep -i "metric"` 在本 spec 的迁移中无命中
- 数据契约：既有 `unique(...)` 仍生效；重跑同一 ingest 新增行数 = 0
- 数据契约：`published_at` 为 NULL 的指标**不得**出现在任何规则/回测查询结果中（有测试锁定）
- 行为：`GET /metrics/latest` 返回含四徽章字段；未登记 `metric_key` 被 registry 拒绝
- 行为：既有猪智投端点（`/industries/{key}/dashboard`）在本改动后仍通过其原测试（**不回归**）
- 门禁：`uv run --extra dev mypy app`；改了读路径后跑 `bash scripts/bench.sh`

- 行为：任取一个历史交易日，按当时的分类归属还原成分股（SCD2 生效），与当日实际分类快照一致

## S1.7 资金流四件套 + 外资画像重构

**范围**：做完之后，资金流指标不再依赖已受限的北向资金每日数据。

**背景（硬事实，2026-10-13 依实机两产地交叉验证修正）**：北向资金**盘中实时**数据 2024-05-13 取消；**每日净买入** 2024-08-19 取消（改按季度披露持股）。
> ⚠️ **修正说明（Ruling 62/63）**：**「每日成交额」并未取消**——上游 `moneyflow_hsgt.north_money` 每交易日仍给值，只是**同一列在 2024-08-19 换了语义**：断点前 148 日有 **83 个负值**（`[-13056.64, 22448.99]`，百万元）＝**净买入**；断点后 502 日**零负值、零零值**（`[77584.24, 510101.29]`）＝**成交额**口径。独立产地东财「当日成交净买额」断点后 **502/502 全空**，与"净买入已取消"一致。
> **故：北向每日净买入判 `不可得`；该列的成交量口径判 `可得但已换语义`——不得把断点后的值呈现为净买入。** 证据见 `docs/design/data-source.md` 附.9。

原设计在 `市场/外资画像` 与 `情绪/资金流向` **两处**依赖它。

**交付物**
- 在 `industry_metrics` 注册 **5 个**新指标（ETF 份额变化 / 两融 / **董监高及关联人净增减持** / **5%+ 股东净增减持** / 南向）
  —— 后两者是 **2026-10-16 依 [ADR 0019](../decisions/0019-official-first-source-layer.md) 拆分的两个 key**：
  覆盖主体、频率、单位与 PIT 能力都不同（实测见 [data-source.md 附.11](../design/data-source.md#附11-官方一手出口复核s17--s19--s112--2026-10-16)）
- `/market/foreign` 重构为「陆股通持仓（季度）」并**改名**（不再叫"外资画像"）
- 情绪 `资金流向` 组改为四件套

**不做什么**
- **不做**"北向资金每日净买入"（数据已不存在）
- **不得**把 `north_money` 断点后的**成交额**口径呈现为"净买入/净流入"（Ruling 63）——该值是活数据、可以展示，但**命名与文案必须体现"成交额"**；断点前的净买入历史如保留，须**显式标注断点与口径**
- **不把**「香港中央结算持仓」称作"外资"——它是名义持有人**汇总账户**（HKEX FAQ），持仓主体不可拆分，故该命名在方法论上是错的
- **不得**把「董监高及关联人」（内部人）与「5%+ 股东 / 实控人 / 机构」（产业资本）两种口径**混进同一个 key** —— 主体、频率、单位、PIT 能力都不同，混装即口径混装（ADR 0019 硬纪律）

**契约**

| 指标 | `metric_key` | 频率 | 说明 |
|---|---|---|---|
| 宽基 ETF 份额变化 | `etf_share_change` | 日 | **"国家队"护盘唯一可见痕迹**，完全公开 |
| 融资余额 / 融券余额 | `margin_financing_balance` / `margin_short_balance` | 日 | 已有（S1.9）|
| **董监高及关联人**持股变动 | `insider_net_change_daily` | 日 | **官方一手**：沪 `COMMON_SSE_XXPL_CXJL_SSGSGFBDQK_S`（带 `FORM_DATE` 披露日）/ 深 `1801_cxda`（**无披露日** ⇒ 不进回测、不进信号链路）。单位统一 **万股** |
| **5%+ 股东 / 实控人 / 机构**增减持 | `industrial_capital_net_change` | 事件驱动 | **官方一手**：巨潮 `hisAnnouncement/query` 类目 `category_gqbd_szsh`（股本变动）；`announcementTime` 即披露时点。金额需抽取（可后置），先交付事件与家数 |
| 南向资金 | `southbound_net_buy` | 日 | 数据仍披露，作港股情绪参照 |

**依赖**：S1.2；`industrial_capital_net_change` 依赖**既有**巨潮公告管道（新增类目即可，**不再等 S3.2 的全量抽取**——
2026-10-16 实测该管道已具备取数能力，见 附.11）；`insider_net_change_daily` 依赖沪深交易所官方接口（自写**时间窗**增量取数）
**验收判据**
- 数据契约（**Ruling 63 修正后的语义判据**，替代原"grep 不得出现每日净买入口径字段名"）：**凡承载 2024-08-19 之后 `north_money` 的字段名、DTO 字段与 UI 文案，必须体现「成交额」口径，不得呈现为「净买入/净流入」**；`grep -rn "北向\|northbound" backend/app/ frontend/src/` 的每一处命中都要能在报告里归类为「断点前的净买入历史（显式标注断点）」或「成交额口径（命名已体现）」——**不得存在把成交额冒充净买入的第三类**
- 行为：陆股通持仓的频率标识为「季度」，且 UI 明示滞后
- 行为：ETF 份额变化有 ≥1 年日频序列
- 行为：四件套每个指标带 `source / as_of`
- 数据契约（2026-10-16 增补）：`insider_net_change_daily` 的沪市行**必须有 `published_at`**（取自 `FORM_DATE`）；
  深市行 `published_at` 允许为 NULL 但必须带 `extra.disclosure_date_unavailable`，且**不得**被任何回测/信号消费
- 数据契约（2026-10-16 增补）：两所**单位归一为万股**（沪原生股、深原生万股），且断言换算系数写死在取数层
- 门禁（2026-10-16 增补）：官方类目采集必须**断言过滤生效**（实测巨潮传无效 `category` 会**静默退化为全量**，
  见 附.11.2 #5）；新增取数路径须有"窗口生效"的反例测试
- 门禁（2026-10-16 增补）：`uv run --project backend python backend/scripts/spike_official_sources.py` 全绿
  （证据可复现，Ruling 51）

## S1.13 情绪/综合情绪指数

**范围**：做完之后，用户看到一个自建的市场情绪综合指数及其历史分位。

**契约**
- **自建 composite**：对 S1.8–S1.12 的指标做分位标准化后加权合成
- **命名禁止用「恐贪指数」**——Fear & Greed 是 CNN 专有名称且为美股七项口径。命名为「市场情绪综合指数」
- 权重与方法**必须公开可查**（在 UI 或文档），且变更时带版本号
- 第三方机构编制的情绪指数**仅作对照展示，不进信号链路**（算法不公开，无法复算）

**依赖**：S1.8–S1.12
**验收判据**
- 数据契约：合成指数有与成分指标等长的历史序列；权重配置可查
  - ⚠️ **2026-10-13 依实测补充（Ruling 66）**：成分窗口极不齐（262 天 / 829 / 1298 / 2010 起 …），「与**所有**成分等长」**不可能同时成立**。落地口径为：**行日历 = 各成分交易日的并集**（故行跨度**等于最长成分**、且**不短于任何成分**），**有值跨度**另行如实报告；**每个有值行的 `extra` 必须记录当日实际参与的成分集合**（可复算的前提）。实测：行 `2010-04-16..2026-10-12`（= 最长成分 `if_basis`）、有值 `2015-08-13..2026-10-12`；**有值天数 2708 ≥ 1260**
  - ⚠️ **S2.2 的前置约束（Ruling 66）**：`window=1260` 的分位必须用 **`range>=6y`（或 `all`）** 读取——`range=5y` 只回 **1214** 个有值日（**<1260**），会算在不完整窗口上
- 行为：给定某一日，用成分指标重算 composite 能得到与库里一致的值（**可复算性测试**，须为**独立实现**而非重读 `extra`；并须做**破坏验证**证明断言非空转）
- 行为：`grep -rn "恐贪\|fear.*greed" frontend/src/ docs/ --exclude-dir=specs --exclude=Changelog.md` **无命中**（⚠️ **2026-10-13 修正（Ruling 65/66）**：原判据未排除 `docs/specs/` 与 `docs/Changelog.md`，而**契约层陈述禁令**、**历史层记录该禁令**都必然命中 → 按字面**不可满足**。判据**意图是禁止产品命名**，故排除这两层；被排除层内的命中**只允许**是禁令陈述本身。测试文件内的用例名不在本判据范围内）
- 行为（Ruling 66 补充）：**最新值的"薄"必须对使用者可见**——各腿最新日不同（`daily_quotes` 锚定的腿止于某日、QVIX 另止于某日），故**最新交易日的参与腿数会显著变少**（实测 `2026-10-12` 仅 **3/11 条腿**、生效权重 0.23，而前一日 `2026-10-09` 有 10 条）。**不得让用户把 3 条腿合成的值读成与 10 条腿等权** → UI 必须明示「当日由 N/11 条腿合成 + 生效权重」，且**下限 0.20 的取值理由须在字典写明**
  - ⚠️ **2026-10-16 修正（Ruling 67）**：上一条要求"薄**值**可见"，实测证明它会把 3 条腿的数字送上头条（读者仍拿它与 10 条腿的值对比），而成因是**编排缺失** —— 这一族指标此前只由手工脚本写、没有日更任务，各腿锚点因此越漂越开。落地口径改为：**薄日不发布值** —— 生效权重之和落在 `[0.20, 0.80)` ⇒ `value = NULL` + `missing_reason='below_publish_weight'`（参与集/逐腿分位/生效权重仍落 `extra`，当时算出的数落 `extra.withheld_value`），闸门常量 `COMPOSITE_PUBLISH_MIN_WEIGHT = 0.80`。Ruling 66 要的"可见性"改由两处承担：①**发布日**的 `extra.participants` / `effective_weight_sum` → UI「当日由 N/11 条腿合成 · 生效权重 w」；②读面新增 `expected_as_of` / `lag_trading_days` / `stale`（三态，`null` ≠ 新鲜）明示"展示的是哪一个**齐备**日"。收敛编排（对账后置、T-1 目标日、10 交易日窗口、落后上限）见 [ADR 0016](../decisions/0016-derived-metrics-converge.md)，口径细节见 [metric-dictionary §4.2「发布闸门」](../design/metric-dictionary.md)
- 行为（Ruling 65 补充）：**自建 composite 允许进信号链路**（S2.2 的示例规则正是消费它）；被禁入信号链路的是**第三方机构编制**的情绪指数（算法不公开、无法复算）
- **契约（Ruling 68，2026-10-17）：当日盘后（T+0）与临时值披露**（[ADR 0020](../decisions/0020-t0-after-close-expected-day.md)）
  - **期望日与齐备性是两个判据，不得合一**：期望日 = 交易日历 + 时钟（交易日 17:30 CST 之后含当日），**不探库**；齐备性 = 对账补齐后按三元组门禁（行数 ≥0.9×universe + `pct_chg` 非空率 ≥0.99 + 该日有限价）逐日回退。合一会造成两种死锁：① 拉取前当日必然无数据 ⇒ 当日永远进不了期望集；② 读面若看齐备性，"今天整天没采"时期望日退回昨天 ⇒ `stale=false`（自指）。
  - **落后交易日数必须由日历计数**，不得用 `daily_quotes` 的实际持有日（"今天没采"时数出 0 ⇒ `stale=false`）。
  - 当日盘后可得 9/11 条腿（缺交易所融资融券两条，合计权重 0.16，T+1 披露），生效权重 0.84 **仍在 0.80 闸门之上 ⇒ 照常发布**（闸门与权重口径不变）。实测依据：2026-10-17 00:2x 探测 7 个上游，除 `margin` 外均含当日。
  - ⚠️ **2026-10-19 实测修正（Ruling 69）**：上一条的前提"QVIX 当晚到位"**不是稳定事实**。当晚 17:48 收敛为 **8/11、生效权重 0.72**（缺 `margin` ×2 + `qvix_50etf`；QVIX 的 CSV 当晚 19:00 后才更新）⇒ 当日值按 `below_publish_weight` **不发布**，hero 退到上一齐备日。故：① 文案**不得**把 `expected_as_of`（日历期望日）写成"各成分指标齐备的数据已到 X"；② 读面新增 `latest_withheld`（被拦日的腿数/权重/缺腿与逐腿原因），把"当日为什么不是它"说清；③ 18:30/20:00 重试 tick 的跳过条件改为"行情齐备 **且** 当日 composite 已发布"（`is_composite_published`），否则 QVIX 迟到时当日值要拖到次日 10:00 的兜底对账。
  - 该值是**临时值**：上游披露后会被收敛器重算改写。读面必须给出 `provisional` **三态**（`true` 会被改写 / `false` 终值 / `null` 判不出，`null` **不得**读成终值），来源是 registry 的 `late_arrival` 声明（不写库、不改口径、不升 `caliber_version`）。
  - 文案**不得承诺"次日"**（实测上游可超一天未披露，承诺时点会失实）。
  - 术语：用户可见文案统一用「**成分指标**」，代码字段名 `legs` / `legCount` / `totalLegs` 与 `extra.participants` 契约不变（Ruling 67 的「N/11 条腿」是内部行话）。
